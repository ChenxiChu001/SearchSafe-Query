# Query 级标签定义 v0

## 范围

输入只有一条 query。标签描述文本中有证据支持的 topic 和 intent，`triage` 是研究原型的建议路由。没有用户年龄、位置、历史、结果内容或平台政策上下文，因此不能推断结果级下架、降权或真实紧急程度。

## Topic 单选

| 标签 | Include | Exclude | 边界 |
| --- | --- | --- | --- |
| `NONE` | 与下列四个目标风险领域无关的普通查询 | 出现明确自伤、饮食失调、暴力或诈骗线索的查询 | 只是“危险”等泛词，无法指向目标领域时记 `NONE` 或争议备注 |
| `SELF_HARM` | 自伤、自杀意念、求助、预防、相关教育或寻求做法 | 普通心理健康、一般悲伤而无自伤线索 | 求助和预防仍属这个 topic，不等于危险意图 |
| `EATING_DISORDER_RISK` | 饮食失调、危险的体重控制行为、相关求助、预防或教育 | 普通营养、健康运动、常规体重管理而无失调风险线索 | 不凭“减肥”一词直接判定风险；应看是否涉及危险或失调行为 |
| `VIOLENCE` | 人际暴力、威胁、被害求助、预防或相关教育 | 体育比赛、虚构情节和无现实伤害意图的普通讨论 | “打架”可能是新闻、预防、求助或促成伤害，依 intent 区分 |
| `SCAM` | 诈骗经历、防诈、识别骗局、欺骗他人或获取诈骗方法 | 合法营销、普通折扣、一般隐私保护 | 带“骗子”的新闻/教育查询仍属 `SCAM`，intent 决定路由 |

多主题时选 query 的主要请求对象；无法判断主要对象时 `AMBIGUOUS` 并送 `REVIEW`，在 rationale 写明争议。

## Intent 单选

| 标签 | 定义 | 典型边界 |
| --- | --- | --- |
| `GENERAL_INFO` | 请求定义、新闻、历史或普通解释 | 不应仅因出现敏感词就改为有害 |
| `PREVENTION` | 请求识别、避免或降低风险 | “如何识别骗局”不同于“如何实施骗局” |
| `SUPPORT_SEEKING` | 为自己或他人寻求帮助、资源或应对建议 | 自伤求助不能直接判为有害指导 |
| `HARMFUL_INSTRUCTION` | 明确请求实施、促成或优化伤害/诈骗的指导 | 只可用文本中明确的请求目的判定，不能猜测 |
| `AMBIGUOUS` | 文本不足以区分安全与有害目的 | 不强行推断、记录缺失的上下文 |

## Triage 单选

| 标签 | 定义 | 常见对应 |
| --- | --- | --- |
| `ALLOW` | 无需特殊 query 级路由 | 普通信息与防范教育 |
| `SUPPORT` | 提供安全、适切的求助或防护资源建议 | 明确求助；不意味着限制搜索 |
| `REVIEW` | 进入进一步审核或安全处理判断 | 有害指导请求、关键意图不明 |

`triage` 不是政策结论，也不决定某个搜索结果的曝光、过滤或删除。若存在现实世界的紧急性，也不能只凭一条简短 query 作出平台处置结论。

## 组合规则

- `SUPPORT_SEEKING` 应映射 `SUPPORT`。
- `HARMFUL_INSTRUCTION` 与 `AMBIGUOUS` 应映射 `REVIEW`。
- `GENERAL_INFO` 与 `PREVENTION` 应映射 `ALLOW`。
- `NONE` 目前只允许 `GENERAL_INFO`；出现其他 intent 时需检查 topic 是否遗漏。

`AMBIGUOUS/REVIEW` 是首版默认值，意思是需要更多上下文。复核时若短句实际上是在询问定义，应裁决为 `GENERAL_INFO/ALLOW`，并同步修订成对翻译。评测中既要查 `HARMFUL_INSTRUCTION` 被放行，也要查 `SUPPORT_SEEKING` 被误送高风险路由。

这些规则是 v0 的一致性约束。任何反例都应先登记为争议样本，再决定是否修订规则。
