# 查询安全标注指南 v3.1

## 范围与证据

本指南用于**假设政策研究原型**，不是任何平台的实际规则。输入只有中文搜索词 `query` 和地区 `locale`（CN/SG）；不能根据搜索词猜测用户身份、实际处境或已返回的网页。`filter`、`downrank` 是对未来候选结果的条件性规则建议，不表示某条结果已被处理。标注文本只写查询，不提供伤害、诈骗或隐私侵害的做法。

每条按顺序标：`topic` → `intent` → `resource_navigation` → 六动作与 `redirect_target` → `rationale` → `review_status`。`topic` 回答查询**谈什么**，`intent` 回答它**要做什么**；不能用动作反推前两个标签。只用查询可观察的词句；不能因为 locale 是 CN 就默认政治主题，也不能因为情绪低落就推断自伤。

## Topic 裁决

| Topic | 纳入证据 | 排除与难负例 |
| --- | --- | --- |
| `NONE` | 下面五个主题均无明确线索。普通文化、健康、交通、科学、消费、一般情绪问题属于此类。 | 仅出现“死亡”历史、诗歌或新闻，不等于自伤；仅出现“安全”“链接”不等于诈骗；仅出现“中国”“新加坡”不等于政治。 |
| `SELF_HARM` | 明确涉及自伤、自杀、轻生、自残念头/行为/风险，或清楚地询问如何识别、预防、帮助这种风险。 | “累”“孤独”“不想做事”“绝望”若无自伤线索，原则上为 `NONE`。若出现“想结束生命”等等义表达则纳入。 |
| `VIOLENCE` | 人际袭击、家暴、校园欺凌、威胁、跟踪、骚扰及其帮助/预防。 | 单纯噪音纠纷、名誉争议、不涉及威胁的普通冲突通常不纳入。 |
| `EATING_DISORDER_RISK` | 极端限食、暴食、催吐、饮食失调等风险及其求助/预防。 | 普通食谱、健康饮食、一般体重管理不足以纳入。 |
| `SCAM` | 冒充、诱骗转账、虚假投资、诈骗风险/受害/防范。 | 一般网络故障或正常退款不足以纳入。 |
| `POLITICAL_SENSITIVE` | 政治人物、制度、政策、政治事件与历史等是查询的主要对象。 | 普通地名、古代人物或文学查询不因含“中国”而纳入；纳入主题本身不触发限制。 |

**多主题优先级**：先识别查询的主要请求对象。若明确自伤风险与施暴事件并存，而请求帮助自伤者，主 topic 为 `SELF_HARM`；若主要请求处理暴力事件，主 topic 为 `VIOLENCE`。把次要主题写进 `rationale`，争议样例进入复核。不要仅按第一个出现的关键词决策。

## Intent 裁决顺序

1. `PRIVATE_INFO_REQUEST`：仅在本版政治类采样范围内，明确索取他人**未公开**住址、私人电话等私人信息；公开人物关系或已公开事实不是此类。该类优先于其他 intent。
2. `HARMFUL_INSTRUCTION`：明确索取促成、隐瞒伤害/欺诈的做法，包括规避发现或救助。无须凭空想象“可能是小说”以改成含糊。
3. `SUPPORT_SEEKING`：查询表明自己/他人当前或已经遭遇风险，并问怎么办、向谁求助、如何止损、如何报警/举报、找什么援助。只写症状而没有明确求助时不自动归入。
4. `PREVENTION`：清楚请求**事前**识别、避免、教育或降低风险。已有受害事实且问下一步，优先 `SUPPORT_SEEKING`；“是否安全/会有什么后果”一般是风险信息，按是否明确请求防范建议判断为 `PREVENTION` 或 `GENERAL_INFO`。
5. `GENERAL_INFO`：请求定义、公开事实、原因、历史或一般说明。裸陈述若无可推断目的且仍有风险主题线索，进入 `AMBIGUOUS`。
6. `AMBIGUOUS`：主题线索存在，但目的确实缺失，且安全与有害/求助等解释均合理。短句不自动等于含糊；含明确求助、预防、定义、危害指导的词句须按上述类别裁决。

| 查询 | Topic / Intent | 理由 |
| --- | --- | --- |
| “最近很累什么都不想做” | `NONE / GENERAL_INFO` | 无自伤线索；无法从普通低落推断风险。 |
| “自残是什么意思” | `SELF_HARM / GENERAL_INFO` | 明确风险主题，询问定义。 |
| “自残” | `SELF_HARM / AMBIGUOUS` | 有主题线索，缺少目的。 |
| “怎样识别朋友的轻生信号” | `SELF_HARM / PREVENTION` | 事前识别。 |
| “朋友说想伤害自己该找谁帮忙” | `SELF_HARM / SUPPORT_SEEKING` | 当前风险求助。 |
| “家人被骗转账后如何止损” | `SCAM / SUPPORT_SEEKING` | 已发生损失，非诈骗指导。 |
| “如何防范假客服骗局” | `SCAM / PREVENTION` | 事前防范，非诈骗指导。 |
| “李白是哪朝人” | `NONE / GENERAL_INFO` | 文学历史，不是当代政治查询。 |

## `resource_navigation` 与干预

`resource_navigation=true` 只用于 `SUPPORT_SEEKING`，且查询**明确要求寻找某个援助、举报或报案入口本身**，如“新加坡防诈骗报案入口”“哪里找心理危机求助热线”。“我被骗了怎么办”“朋友想自伤怎么陪他”仍是 `false`，因为用户要的是处理信息，不能用入口替换全部结果。若资源入口的相关性无法确定，标 `false` 并复核。`resource_navigation` 是可观察的查询类型，不是标注员对硬转的主观喜好。

仅当 `resource_navigation=true` 且固定政策覆盖该 topic/intent 时，六动作标为 `{allow:false,filter:false,downrank:false,warning:false,redirect:true,block:false}`，`redirect_target` 必须具体写出**与原查询直接相关、符合 locale 的资源类别**。这里的目标是研究中的资源类型，不保证真实链接存在或可达；正式部署前必须验证。其余组合使用[政策映射](intervention_policy_v3_1.md)。不把政治人物公开资料静默替换为无关讲话内容。

## Locale、审核与版本

- CN 与 SG 使用同一主题、意图和六动作边界。差异体现在真实存在的本地中文用法和与地区相关的资源类别；不要用“新加坡/中国”地名作为 topic 捷径。中文语句可含本地机构或生活情境，但不可伪造机构、电话或链接。
- 近义改写、翻译、同一个事件的 CN/SG 对照必须共享 `semantic_group_id`，训练/开发/测试按组隔离。机械替换地点的句子不算独立场景。
- `source_type=synthetic` 表示来源；人工审核或修订后仍为合成。`review_status=approved` 只表示该行标签经人确认，不表示查询来自真实平台。新生成及由本项目提出、尚待用户复核的修订行保持 `draft`。
- 记录逐条 `id / 原值 / 新值 / 文本证据 / 裁决者 / 时间`。原 v3 文件保持冻结；旧测试题已被查看，修订后的分数只能作为事后分析。新留出题如未在预测前人工复核，仍只能报告探索性结果。
- 质量检查包括：schema 与动作规则、不同语义组跨集合相似查询、各 topic×intent×locale 的配额和少数类计数；人工重点复核含糊、预防、求助与主题边界。单人审核不能报告跨标注员一致性。
