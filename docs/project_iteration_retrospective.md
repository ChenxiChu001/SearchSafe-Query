# 从 48 条边界样例到 v3.1：SearchSafe Query 的迭代记录

## 核心结论

- 项目从 **48 条中英成对合成样例**和三档 `triage` 起步，逐步形成六类主题、六种意图、六个可组合干预动作的**假设政策研究原型**；v3.1 候选集为 **1400 条中文查询、1399 个语义组**。规模扩大解决了早期覆盖窄、地区与主题混杂的问题，也暴露了新的标签边界与动作一致性问题。
- 真正可比的训练增益要看**同题、同 Prompt**：v2.1 直接输出路线的六动作整组从基础模型 **17/62** 升到 **50/62**；v3 在它自己的新测试题上从 **40/200** 升到 **158/200**；v3.1 在另一批新题上比旧 v3 适配器从 **64/100** 升到 **78/100**。这些数字来自不同的合成草稿测试集，**不能串成一条连续上升的性能曲线**。
- 增加数据不等于风险已经解决。v3.1 新题的硬重定向只命中 **2/12**，唯一 Block 草稿题漏判；在旧 200 题、同一 v3.1 Prompt 的回归测试中，v3.1 虽比 v3 的六动作整组 **117/200 → 143/200**，Block 却从 **5/10 降到 3/10**。所有结果均为内部探索性诊断，尚无经预测前盲审的 Gold 测试集或真实搜索结果级验证。

| 版本 | 候选行 / 语义组 | 查询语言 | 主要新增能力 |
| --- | ---: | --- | --- |
| v0 | 48 / 24 | 中文＋英文 | 五类 Topic、五类 Intent、三档 Triage |
| v2 | 248 / 123 | 中文＋英文 | 第六类政治主题、私人信息请求、六个可组合动作 |
| v2.1 | 328 / 163 | 中文＋英文 | 政治边界扩充、按组留出、两条 QLoRA 路线 |
| v3 | 1000 / 999 | 全中文，CN＋SG | 六类主题跨地区覆盖、更多独立场景和难负例 |
| v3.1 | 1400 / 1399 | 全中文，CN＋SG | 更细指南、SG 场景、资源入口硬重定向；本轮仅训直接路线 |

## 一、最初的 48 条：先验证标签体系和错误类型

首版 `v0` 由项目用 AI 辅助起草 **24 个语义场景**，每组写中文、英文各一条，共 **48 条**；全部标为 `source_type=synthetic`、`review_status=draft`。Topic 是 `NONE`、自伤、饮食失调风险、人际暴力、诈骗五类；Intent 是一般信息、预防、求助、有害指导、含糊五类。标注顺序为 **Topic → Intent → Triage → 一句话文本依据**，Triage 只有 `ALLOW / SUPPORT / REVIEW`。翻译与近义句用同一 `semantic_group_id`，设计重点是“相似风险词，不同用户目的”的边界，而不是模拟真实搜索流量。[原始数据](../data/canonical/candidates_v0.jsonl)、[首版标签定义](../policy/taxonomy_v0.md)、[首版标注指南](../policy/annotation_guideline_v0.md)。

未微调的本地 **Qwen3.5 9B 4-bit** 用固定 Prompt 跑完 48 条，三字段 JSON 可解析 **48/48**；与草稿标签一致的 Topic **48/48**、Intent **42/48**、Triage **43/48**。但 8 条标为 `AMBIGUOUS` 的样例仅 **2 条**被预测为含糊，说明模型容易从短句补出用户目的。关键词对照在同题上的 Topic/Intent/Triage 分别是 **40/48、16/48、24/48**，还把 8 条求助中的 6 条送进 `REVIEW`。这说明只看风险词会误伤求助，也说明 9B 的高总体一致数掩盖了含糊类问题。此时**没有正式微调**；两步 QLoRA 只验证本机训练与适配器加载链路。[首版基线与错例](../evaluation/error_analysis_v0.md)、[首版数据](../data/canonical/candidates_v0.jsonl)。

## 二、v2 与 v2.1：从单一路由到可组合动作，并首次做留出训练

| 版本 | 数据和变化 | 解决的问题 | 同版可核查的结果 |
| --- | --- | --- | --- |
| **v2** | 旧 48 条按新策略重标，再加 200 条中英合成查询，合计 **248 行、123 组**；增加 `POLITICAL_SENSITIVE` 10 行和 `PRIVATE_INFO_REQUEST` | 三档 Triage 无法表达“保留安全结果，同时过滤、降权、提示或引导”；政治类仅作少数 Block 边界示例 | 9B 零样本直接输出六动作整组 **54/248**；把预测的 Topic/Intent 交给固定规则后，已覆盖的 **219/247** 与草稿动作一致。后者是规则执行对照，不是训练提升 |
| **v2.1** | 再加 **80 条政治类草稿**，共 **328 行、163 组**；中英各 164 行。首次按语义组冻结 **202/64/62** 训练、开发、测试 | 政治类从 10 行扩到 90 行，为公开信息、隐私泄露求助、私人信息索取提供更多边界；开展两条路线的 QLoRA 比较 | 在同一 62 题上，直接路线基础模型 **17/62 → QLoRA 50/62**（+53.2 个百分点）；标签→规则 **54/62 → 56/62**（+3.2 个百分点） |

v2 将输出从 `triage` 改成 `{allow, filter, downrank, warning, redirect, block}` 六个布尔值。`filter/downrank` 的含义是**建议在出现相应候选结果时启用规则**，并不表示已经过滤了任何真实结果。`block=true` 与其余动作互斥，只用于本假设政策中明确索取未公开私人信息的场景；普通政治信息不因主题本身受限。`redirect_target` 记录与原查询相关的资源类型。直接输出和“标签→固定规则”成为两条可比较的工程路线。[v2 策略](../policy/intervention_policy_v2.md)、[v2 草稿基线](../evaluation/error_analysis_v2.md)。

v2.1 的直接路线训练后多动作执行明显更符合草稿政策，但 Topic Macro F1 从 **0.963 降到 0.885**；标签路线的动作增益只有 2 题。质量审计还发现 **72 条 CN 查询全部是政治类**，地区与主题严重混杂；62 条测试行只对应约 **30 个相似度泄漏簇**，Block 正例只有两个独立语义组。因此这轮适合验证训练流程和揭示问题，无法证明地区能力或稳定 Block 召回。旧 248 条由项目所有者单人整批接受，新增 80 条仍为草稿。[v2.1 质量审计](../evaluation/data_quality_v2_1.md)、[训练比较](../evaluation/training_comparison_v2_1.md)。

## 三、v3：1000 条纯中文，解除地区捷径并加大意图边界覆盖

v3 改为 **1000 条中文合成查询、999 个语义组**。配额为 `NONE` 120、自伤/饮食失调风险/暴力/诈骗各 200、政治 80；`GENERAL_INFO` 降至 **310/1000**。每个 Topic 都覆盖约 **CN 70% / SG 30%**，使模型不能再简单用地区猜政治主题。旧 v2.1 的 **164 条中文行全部进入训练**；新数据分成 **700 train / 100 dev / 200 新测试**，旧测试退出正式比较。六动作政策保持不变，仍同时训练标签→规则和直接输出两条 QLoRA 路线。[v3 数据审计](../evaluation/data_quality_v3.md)、[训练记录](../training/README_V3.md)。

在**同一批 v3 新 200 题、同一 v3 Prompt**上，直接输出基础模型的六动作整组为 **40/200**，v2.1 适配器为 **129/200**，v3 适配器为 **158/200**。v3 相对 v2.1 在同题上提高 **14.5 个百分点**；相对基础模型提高 **59.0 个百分点**。标签→规则路线同样由 v2.1 的 **129/200** 到 v3 的 **158/200**。v3 直接路线的 Topic Macro F1 **0.930**、Intent Macro F1 **0.683**；`NONE` Recall **22/24**，`SELF_HARM` Recall **31/39**。但 `AMBIGUOUS` Recall **9/28**、`PREVENTION` Recall **8/24**，说明动作总分上升并未解决意图边界。[v3 同题比较](../evaluation/training_comparison_v3.md)。

逐题审计揭示另一层问题：部分旧草稿标签本身与查询不符。例如标为自伤的普通低落或死亡文学、标为诈骗有害指导的防范/止损问题、标为预防的已受害求助。旧 24 条 `PREVENTION` 中，项目按更细指南**建议**将 17 条改为求助、含糊或一般信息；这是看过预测后的修订意见，不能倒过来宣称旧模型真实召回更高。v3 测试 200 条在预测前均未人工盲审，仍是探索性数据。[v3 错例审计](../evaluation/v3_error_analysis.md)。

## 四、v3.1：修订指南、补 SG 难例，加入少量硬重定向

v3.1 保留原 v3 冻结文件，形成 **1400 条中文候选**：继承原 1000 条，新增 **300 条训练查询**和**100 条新留出题**；总计 **1399 个语义组**。项目记录了对旧行的 **85 条建议修订**，这些行和 400 条新增行仍保留 `draft`；其余旧行按用户的整批审核接受声明记录状态。数据集当前 train/dev/test/历史测试分别为 **1000/100/100/200**。新训练查询以 SG 中文场景、`NONE↔SELF_HARM`、`AMBIGUOUS↔PREVENTION↔SUPPORT_SEEKING` 的难例为重点。[v3.1 数据质量](../evaluation/data_quality_v3_1.md)、[复核记录](../docs/review_attestation_v3.md)。

策略没有因地区而改动六动作边界；变化是把“**明确寻找求助、举报或报案入口本身**”定义为 `resource_navigation=true`，才可硬重定向（`allow=false, redirect=true`，其余动作 false），目标资源类型要与查询和地区相关。普通“我该怎么办”仍保留安全结果并增加引导。指南还明确：一般低落不自动算自伤、已经受害后的应对优先判求助、症状陈述不自动算预防、普通政治讨论不自动限制。[v3.1 标注指南](../policy/annotation_guideline_v3_1.md)、[策略补充](../policy/intervention_policy_v3_1.md)。

因时间约束，本轮**只训练直接输出路线**。仍用 Qwen3.5 9B 4-bit 的 QLoRA，在旧 dev 损失第 400 步最低时保留该检查点，训练保存到第 600 步后按事先记录的规则停止。[训练与检查点说明](../training/README_V3_1.md)。在同一批**全为草稿**的 100 条新题、同一 v3.1 Prompt 上：

| 模型 | Topic Macro F1 | Intent Macro F1 | 六动作整组 | 重要护栏 |
| --- | ---: | ---: | ---: | --- |
| 基础模型 | 0.926 | 0.646 | **49/100** | 有害指导漏 `filter` 8/8 |
| v3 直接适配器 | 0.873 | 0.772 | **64/100** | 有害指导漏 `filter` 1/8 |
| v3.1 直接适配器 | 0.902 | 0.863 | **78/100** | 有害指导漏 `filter` 0/8，但硬转只 2/12、唯一 Block 草稿题漏判 |

v3.1 对 v3 的六动作整组提高 **14.0 个百分点**，Intent Macro F1 提高 **9.1 个百分点**。同时，`NONE` Recall 只有 **12/20**，`AMBIGUOUS` Recall **7/16**；`filter/downrank` 的 Recall 都是 **62/64**、Precision 都是 **62/78**，其中 16 条误开启有 10 条来自“应完全替换结果却仍保留普通结果处理”的硬转错题。这些错因需要分开修，不应只补更多 `filter=true` 句子。[v3.1 新题比较与分析](../evaluation/training_comparison_v3_1.md)。

### 用旧 v3 的 200 题做回归检查

旧 200 条查询与原标签保持冻结。为分清 Prompt 的影响，重新用**同一 v3.1 Prompt**运行旧 v3 与新 v3.1 直接输出适配器，并将原 v3 Prompt 下的历史分数单列：

| 适配器 / Prompt | 六动作整组 | Topic Macro F1 | Intent Macro F1 | `PREVENTION` Recall | Block 命中 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v3 / 原 v3 Prompt（历史） | **158/200** | 0.930 | 0.683 | 8/24 | 10/10 |
| v3 / v3.1 Prompt | **117/200** | 0.900 | 0.624 | 4/24 | 5/10 |
| v3.1 / v3.1 Prompt | **143/200** | 0.895 | 0.619 | 5/24 | 3/10 |

**同 Prompt 下**，v3.1 的整组一致比 v3 高 **13.0 个百分点**，有害指导漏 `filter` 从 **4/36** 降至 **0/36**；但 Block 从 **5/10** 退到 **3/10**，v3.1 的 5 条解析失败全部发生在 Block 题上。原 v3 Prompt 下的 **158/200** 不能直接与新 Prompt 下的 **143/200** 归因为训练造成的下降，因为 Prompt 一换，旧 v3 适配器本身就从 **158/200** 变为 **117/200**。这也说明前面“v3.1 新 100 题 78/100”不足以证明旧边界不退步。[旧 200 题复测、逐类指标与敏感性分析](../evaluation/v3_1_on_v3_test_comparison.md)。

旧 200 题仍是合成草稿。项目对其中 Topic **13** 条、Intent **45** 条、动作 **43** 条提出过事后修订；用这些尚未独立裁决的标签重算，同 Prompt 六动作整组为 v3 **131/200**、v3.1 **162/200**。这只能说明指标对标签版本很敏感。`PREVENTION` 仍需要更难、更可信的测试：新 100 题的 18 条预防正例全部有明显事前识别词，旧 200 题的 24 条预防草稿中仅 3 条有类似词面线索。

## 五、如何正确讲述“不断优化”

这个项目的迭代不是单纯把行数做大：**先定义可观察的 Topic/Intent 边界，再把单一路由拆成多动作政策；发现直接生成动作与标签脱节后加入固定规则对照；发现翻译对和地区捷径后改成中文独立场景与跨 Topic 地区覆盖；发现草稿错标后细化标注指南并记录逐条修订；最后用新测试和旧题回归同时检查收益与退步。**

目前最可信的数字是每个版本内的**同题、同 Prompt 对照**。跨 v0、v2.1、v3、v3.1 的测试题规模、政策输出、语言和审核状态不同，不能把 43/48、50/62、158/200、78/100 当成同一个指标的时间序列。六动作分数衡量模型与**本项目假设政策标签**的一致性，不能证明平台真实过滤、降权或用户体验。全部查询为合成；没有独立双人标注、真实流量先验或候选搜索结果级标签。

下一步应先人工裁决已暴露的 `PRIVATE_INFO_REQUEST→Block`、硬转/软引导、普通查询误判风险主题等边界，给直接输出加独立的固定政策一致性校验，并在**新的、预测前审核的留出题**上重测基础模型和适配器；需要评估真实 `filter/downrank` 时，再加入获准脱敏的查询及候选结果。当前 v3.1 适配器不应仅凭新 100 题的总分被视为各安全护栏全面改善。
