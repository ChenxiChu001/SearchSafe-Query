## 解释边界

- 两条同 Prompt 运行用同一批冻结查询、同一 v3.1 Prompt；只有适配器不同。这是当前最可比的模型对照。原 v3 Prompt 的历史分数单列，不与新 Prompt 的分数直接归因。
- v3.1 新政策加入硬重定向，而旧题的六动作标签按原政策制定；若新模型给出硬转，原标签会算错。逐题原始输出、解析失败和动作错例保存在 JSON 与 raw 文件。
- 原测试题已被查看，且 200 条均为合成草稿；结果不能替代新题盲审或真实流量评估。

## 结果解读与下一步

**总体动作有改善，但 Block 退步。** 同一 v3.1 Prompt 下，v3.1 适配器的六动作整组比 v3 适配器多对 **26/200**（143 对 117，+13.0 个百分点），其中同题修正 40、退步 14；有害指导漏 `filter` 从 **4/36** 降到 **0/36**。同时，Block 从 v3 的 **5/10** 降到 v3.1 的 **3/10**。v3 使用其原 Prompt 时为 **10/10**，说明改 Prompt 本身也显著改变输出；无法将历史的 158/200 与新 Prompt 下的 143/200 直接当作训练退步幅度。旧 10 条 Block 题仍只来自政治人物家属私人信息这一狭窄场景，不足以估计真实召回，但 3/10 是必须处理的回归信号。

v3.1 的 **5 条解析失败**均是这 10 条 Block 题，原始输出给出了 `allow=false`、`redirect=true` 却仍开启 `filter/downrank` 的冲突组合；另有 1 条正确预测 `PRIVATE_INFO_REQUEST` 却没有 Block。于是 Block 失败中既有**结构错误**，也有**标签对、动作错**。这说明仅靠直接生成六动作，不能保证执行“私人信息请求仅 Block”的已写明政策。下一次训练或使用前，应对该组合加入显式一致性校验，并建立独立的隐私请求与相邻公开信息压力测试；校验后的结果须与原始模型分数分别报告。

`PREVENTION` 在旧原标签上仍弱：v3.1 Precision **5/8**、Recall **5/24**，同 Prompt 的 v3 是 **4/9、4/24**。按项目**事后建议**修订标签后，v3.1 的该类 Recall 是 **6/13**，v3 为 **8/13**；修订发生在旧预测已被查看之后，不能把它当作正式性能。相比之下，v3.1 新 100 题中的 18 条预防正例全部带明确事前线索，v3 适配器已命中 18/18。这进一步证明新旧测试难度、标注边界和 Prompt 均不同；需要新的、预测前审核的“隐含预防 vs 事后求助 vs 风险信息”对照题。

项目建议修订的 43 条动作标签会将同 Prompt 六动作整组从 v3 的 **117/200**、v3.1 的 **143/200**，分别变成 **131/200**、**162/200**。这个敏感性差异量化了草稿标签的影响，却不能用来宣称正式提升。结论是：v3.1 在旧题的**总体动作一致性**上优于同 Prompt 的 v3，但 `PREVENTION` 与 Block 仍是未解决的问题；在这些护栏修复、标签独立复核之前，不应仅按总分选择适配器。
